# 交互规范

版本：v1.0

## 1. 交互设计目标

宝宝日记是一款高频、低压力的宝宝成长记录应用。

**交互目标**：

- 快速记录
- 减少操作步骤
- 降低用户负担
- 让记录像聊天一样自然

**核心原则**：

> 用户记录宝宝，而不是操作一个复杂系统。

## 2. 交互原则

### 2.1 少打断

默认不要弹窗。优先使用：页面内反馈、Bottom Sheet、Toast。

禁止频繁使用：确认弹窗、提示弹窗、强制引导。

### 2.2 渐进展示

复杂功能默认隐藏，用户需要时展开。

例如快速记录：默认只显示 `+`，点击后展开喂奶 / 睡眠 / 尿布 / 辅食等。

### 2.3 即时反馈

所有用户操作必须有反馈。

例如点击记录：立即按钮状态变化 + Toast + 数据更新。避免点击后没有反应。

## 3. 页面跳转规则

| 层级 | 方式 | 示例 |
|---|---|---|
| 一级页面 | Bottom Navigation | 首页 / 记录 / 成长 / 我的 |
| 二级页面 | 页面进入 | 首页 → 查看今日状态 → 详情页 |
| 三级操作 | Bottom Sheet | 首页 → `+` → 快速记录 |

## 4. Bottom Sheet 规范

**使用场景**：

- 适合：新增记录、快捷操作、选择类型
- 不适合：展示大量内容、长流程编辑（改用独立页面）

### Anatomy

```text
Bottom Sheet
├── Drag Handle（拖拽条，必须）
├── Header（标题区，可选）
│   ├── Title
│   └── Close Action（可选）
└── Content（内容区）
    └── [Primary Action]（可选，固定底部或随内容滚动）
```

### Layout

| 属性 | 规则 |
|---|---|
| 顶部圆角 | `radius.xl` |
| 顶部 Drag Handle | 宽 40dp / 高 4dp / 圆角 `radius.pill` / 色 `color.border.subtle` / 距顶 `spacing.sm` |
| 最大高度 | 不超过屏高 80% |
| 内容超过高度 | Content 区域可滚动（`ScrollViewer`），Drag Handle 和 Header 固定不滚动 |
| 遮罩 | `color.overlay.scrim` |
| 动画 | 从底部滑入，`motion.duration.normal` |

### Header 规则

- Header 非必须。如 Content 本身已表达清晰（如 Quick Record Sheet 的图标网格），可不设 Header。
- 如设 Header，Title 使用 `font.size.cardTitle` (18sp Medium)。
- Close Action（关闭按钮）可选，放 Header 右侧；若不设，用户通过下滑或返回键关闭。

### 关闭规则（强制）

| 关闭方式 | 规则 |
|---|---|
| 点击遮罩 | ✓ 允许（默认） |
| 下滑 | ✓ 允许（默认） |
| 返回键 | ✓ 允许（默认） |
| Loading / Submitting 期间 | ✗ 禁止上述三种关闭方式，除非有明确"取消操作"逻辑且后端支持取消 |

### Primary Action 位置

- 若 Sheet 内有 Primary Action（如"保存"）：默认固定在底部，不随内容滚动。
- 若内容很短不会滚动，Primary Action 可随内容放在 Content 末尾。
- 禁止 Primary Action 既不固定也不在可见区域内（用户需要滚动才能找到主操作）。

### 嵌套规则

- **禁止** Sheet 内嵌 Dialog。需要二次确认时，关闭 Sheet 后再弹 Dialog，或直接在 Sheet 内用 inline 确认（如二次确认按钮变 Danger）。
- **禁止** Sheet 内嵌另一个 Sheet。需要进一步选择时，用页面跳转或 inline 展开。

### Loading 状态

- Sheet 内异步操作（如保存记录）：操作按钮进入 Loading 状态，禁止重复触发。
- Loading 期间按上述"关闭规则"禁止关闭。

## 5. + 按钮交互规范

**默认状态**：首页只显示 `+`，不要展开九宫格。

**点击后**：显示 Quick Record Sheet，内容：🍼 喂奶 / 😴 睡眠 / 💩 尿布 / 🌡 体温 / 💊 用药 / 🥣 辅食 / 📏 成长。

**关闭方式**：

- 点击遮罩关闭
- 下滑关闭
- 返回键关闭

## 6. AI 记录交互

**产品定位**：AI 记录是重要的记录方式之一，用于降低自然语言记录成本，不是聊天功能。

记录入口体系：

```
记录
├── 快速记录
├── 手动记录
└── AI 辅助记录
```

AI 可以是重点入口，但产品能力层级仍然是"记录优先，AI 辅助"，不要形成"AI → 记录"的导向。详见 [`design-language.md`](design-language.md) 的"产品核心层级"。

### 输入流程

```
用户输入：宝宝下午喝了 120ml 奶

系统 AI 识别：
  类型：喂奶
  时间：下午
  数量：120ml

用户确认：保存
```

### AI 识别失败

不要报错。应允许用户修改。

示例：

```
我没有理解，可以选择记录类型：
🍼 喂奶  😴 睡眠  💩 尿布
```

## 7. AI 次数限制交互

| 状态 | 条件 | 交互 |
|---|---|---|
| 正常 | 剩余 > 2 次 | 显示"今日剩余 8/10 次" |
| 接近限制 | 剩余 ≤ 2 次 | 提示"今日 AI 记录剩余 2 次，升级会员获得 100 次每日额度" |
| 用完 | 剩余 0 次 | **不阻止记录**，提供快速记录入口："AI 次数已用完，可以继续使用快速记录" |

## 8. Record Timeline 交互

**时间轴定位**：记录页面展示所有宝宝事件。

示例：

```
09:30  🍼 喂奶    120ml
11:20  😴 睡眠    1 小时
```

### 筛选

支持标签筛选：全部 / 喂奶 / 睡眠 / 尿布 / 辅食 / 用药。

### 编辑

点击记录进入详情，支持修改和删除。

### 删除

不要直接删除。必须轻提示确认："删除这条记录？"。确认按钮使用 Danger Button（见 [`components.md`](components.md) 5.1.6）。

## 9. 手势规范

| 手势 | 用途 | 规则 |
|---|---|---|
| 上下滑动 | 列表滚动 | 支持 |
| 左滑 | 记录操作（如删除） | **仅用于记录**，不要所有地方都支持左滑 |
| 长按 | 高级操作 | 谨慎使用，只用于高级操作 |

## 10. Loading 状态

| 场景 | 规范 |
|---|---|
| 数据加载 | 优先骨架屏 |
| AI 生成 | 显示"AI 正在整理宝宝记录..."，不要复杂动画 |

## 11. Empty State

无数据时不要显示空白。

示例：

```
今天还没有记录
点击 + 开始记录宝宝成长
```

## 12. Error Handling

### 网络错误

| 项 | 内容 |
|---|---|
| 禁止 | 技术错误（如 `Network Error`） |
| 应该 | "暂时无法连接，请稍后重试" |

### AI 错误

| 项 | 内容 |
|---|---|
| 禁止 | 暴露模型错误（如 `API timeout`） |
| 应该 | "AI 暂时没有完成分析，可以稍后再试" |

## 13. Animation Rules

**推荐动画**：时长使用 `motion.duration.normal`，用于页面切换、Bottom Sheet、状态变化。

**禁止**：大量粒子动画、自动播放动画、影响记录效率的动画。

## 14. Accessibility

交互元素必须：

- 可点击区域 ≥ 40×40dp
- 重要核心操作可点击区域 ≥ 48×48dp
- 文字清晰
- 颜色不能作为唯一提示

### Visual Size ≠ Touch Target（强制）

> 视觉尺寸不等于实际点击区域。允许视觉尺寸小于实际点击区域。

```text
32dp Button
外部实际点击区域达到 40×40dp
```

- Visual Size：控件自身的视觉大小，可以为 32 / 40 / 48dp。
- Touch Target：实际可点击区域，必须满足上述最低要求。
- 实现时通过 Padding / HitTest 区域扩大 Touch Target，不必放大视觉尺寸。

### 其他可访问性要求

- **桌面端鼠标操作**：鼠标 Hover 须有视觉反馈（由平台主题统一处理，业务页面不自行定义 Hover 色）。
- **键盘 Focus**：所有可交互组件必须支持键盘 Focus，Focus 状态使用 `color.border.focus`，不得只依赖颜色变化或阴影。
- **最小文字可读性**：正文不得低于 `font.size.body`，辅助信息不得低于 `font.size.caption`。
- **Icon Button Accessible Label**：Icon Button 必须提供 Tooltip（Desktop）或 Accessible Label，供屏幕阅读器朗读。

## 15. AI Development Rules

AI 修改交互时的开发规则统一见 [`components.md`](components.md) 的"AI 开发规则"章节（含 AI 生成 UI、AI 新增组件、AI 修改交互三组规则）。

## 16. 最终交互目标

宝宝日记交互体验应该接近：

- 微信的自然记录
- Notion 的信息组织
- 宝宝成长助手的温暖感

最终：用户打开 APP——3 秒知道宝宝状态，1 步完成记录，不需要学习。
